Mcaster1 Install System

A cross-platform installer authoring suite. Create professional installers for macOS, Windows, and Linux from a single YAML project file — no scripting required.

Mcaster1 Install Studio

IDE for creating .mis installer spec files. 9-tab editor, build queue, code signing.

Mcaster1 Installer

Runtime wizard. Reads a .mis manifest and installs your application.

.mis Files

YAML installer spec. Describes app metadata, files, shortcuts, prerequisites, and more.

Quick Start

  1. Launch Mcaster1 Install Studio
  2. Fill in App Info — name, version, publisher
  3. Go to Files — add your payload files to the Core component
  4. Select target platforms in Build — macOS, Windows, and/or Linux
  5. Click Build Installer
  6. Click Test Installer to preview the wizard before distributing
Tip: Use File → Import NSIS Script or Import Inno Setup Script to migrate an existing Windows installer in seconds.

Typical Workflow

  1. New Project — File → New Project (⌘N)
  2. App Info — fill in all fields; set install directory defaults per platform
  3. Files — create components; drag in payload files; set destinations
  4. Prerequisites — add runtime requirements (.NET, Homebrew, etc.)
  5. Shortcuts — add macOS Dock / Windows Start Menu shortcuts
  6. Registry — (Windows only) add registry entries for app settings
  7. Security — configure code signing credentials
  8. Custom Actions — add post-install scripts if needed
  9. Build — pick platforms, choose output directory, click Build
  10. Test — click Test Installer to run the wizard locally

Install Directory Defaults

Set the default install paths per platform. Users can change these at install time unless Allow Custom Dir is unchecked. Use path tokens like {name} and {publisher} to keep paths generic.

macOS
/Applications/{Name} ~/Applications/{Name}

System-wide vs user-only. Avoid spaces in publisher names.

Windows
C:\Program Files\{Publisher}\{Name} C:\Program Files (x86)\...

64-bit vs 32-bit apps. Use %APPDATA%\{Name} for user-only.

Linux
/opt/{publisher} /usr/local ~/.local/share/{publisher}

/opt for vendor software; ~/.local for no-root installs.

Files & Components

Organize your payload into components. Each component is an independently selectable unit in the installer.

File destination tokens

TokenResolves to
{install-dir}The install directory chosen by the user
{name}App name from App Info
{publisher}Publisher from App Info
{version}Version from App Info

Component flags

  • Required — cannot be deselected by the user; always installed
  • Selected by default — pre-checked in the wizard; user can uncheck
  • Platforms — comma-separated list; leave empty to install on all platforms
  • Depends — other component IDs that must be selected first
Best practice: Always have at least one required core component containing the main application binary. Optional components (themes, templates, extras) should be separate components.

Security & Code Signing

macOS

  • Signer — "Developer ID Application: Your Name (TEAM_ID)" — from your Apple keychain
  • Team ID — 10-character alphanumeric; found in developer.apple.com
  • Hardened Runtime — required for notarization; enables security restrictions
  • Notarize — submits to Apple's notarization service after signing
  • Profile — xcrun notarytool store-credentials profile name

Windows

  • PFX path — path to your Authenticode code-signing certificate (.pfx / .p12)
  • Timestamp URL — e.g. http://timestamp.sectigo.com — ensures signature survives cert expiry

Linux

  • GPG Key — key ID or fingerprint used to sign .deb packages
  • Sign .deb packages — adds GPG signature to Debian package metadata
Important: Certificate passwords are never stored in the .mis file. You will be prompted for them at sign time.

Prerequisites

Prerequisites are software requirements that are checked before installation begins. The installer runs each check command and shows a pass/fail table to the user.

Fields

FieldDescription
IDMachine identifier, e.g. dotnet48, vcredist2022
NameHuman-readable name shown in the wizard
Check CommandShell command. Exit 0 = present. Non-zero = missing.
Install CommandURL or shell command shown to the user if missing.
PlatformsComma-separated (macos, windows, linux). Empty = all.

Check Command Examples

# macOS: check for Homebrew
which brew

# Windows: check for .NET 4.8 registry key
reg query "HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full" /v Release

# Linux: check for an installed package
dpkg -l libssl-dev | grep -q "^ii"

# Universal: check for a binary on PATH
which openssl
Advisory mode: The installer never blocks the user from proceeding, even if prerequisites are missing. The check page is informational — it shows what's needed and provides download links.

Custom Actions

Custom actions are shell commands or scripts that run at specific points during installation.

Trigger Points

TriggerWhen it runs
before-installBefore any files are copied to the destination
after-installAfter files are copied and shortcuts are created
before-uninstallBefore the uninstaller removes files
after-uninstallAfter all installed files are removed

Action Types

  • shell — a single shell command (run via sh -c / cmd.exe /c)
  • script — path to a script file included in your payload

Examples

# Set executable permissions after install (macOS/Linux)
chmod +x "{install-dir}/MyApp.app/Contents/MacOS/myapp"

# Create a data directory
mkdir -p "{install-dir}/data"

# Register a service (Windows)
sc create MyService binPath= "{install-dir}\myservice.exe" start= auto
Use {install-dir} tokens in your commands — they resolve to the actual installation path at runtime.

Building Installers

Target platforms

  • macOS (.dmg) — requires: Xcode Command Line Tools, hdiutil
  • Windows (.exe via NSIS) — requires: makensis (brew install makensis or nsis.sourceforge.io)
  • Linux (.deb / AppImage) — requires: dpkg-deb (Linux) or appimagetool

Build steps (automatic)

  1. Manifest validated (required fields, at least one component)
  2. Backend validated (tools present, paths correct)
  3. Output directory created
  4. Each selected platform built sequentially in a background thread
  5. Build log shown in real time; progress bar advances per platform

Runtime Installer Wizard

The Mcaster1Installer.app binary accepts a .mis file as its first argument and presents a wizard to the end user.

PageIDDescription
Welcome0App name, version, description, publisher
License1License text; user must accept to proceed
Prerequisites2Check-command table; "Recheck All"; advisory (non-blocking)
Components3Optional component selection; required components pre-checked
Directory4Install directory picker with platform-appropriate defaults
Ready5Summary of app, directory, selected components
Installing6Progress bar; background file copy + shortcuts + registry
Finish7Success / failure; optional launch-app checkbox

The Prerequisites page is only shown when the manifest contains at least one prerequisite. All other pages are always shown.

Install Directory Guide

Choose installation paths that follow platform conventions. The runtime wizard shows these as defaults that users can override.

macOS

System-wide (recommended)
/Applications/{Name} /Applications/{Publisher}/{Name}

Requires admin. Visible to all users. Standard macOS convention.

User-only (no admin)
~/Applications/{Name}

No admin required. Only visible to current user.

macOS tip: Avoid spaces in publisher names when they appear in paths. Use {publisher} tokens so the publisher name is always consistent.

Windows

64-bit apps
C:\Program Files\{Publisher}\{Name}

Standard location. Requires admin.

32-bit apps
C:\Program Files (x86)\{Publisher}\{Name}

WOW64 programs. Requires admin.

User-only (no admin)
%LOCALAPPDATA%\{Publisher}\{Name} %APPDATA%\{Publisher}\{Name}

No admin required. Use LOCALAPPDATA for local data; APPDATA for roaming.

Windows tip: If your app writes to its install directory at runtime (logs, config files), prefer %APPDATA% or %LOCALAPPDATA% to avoid UAC elevation prompts on every write.

Linux

Vendor software
/opt/{publisher} /opt/{publisher}/{name}

FHS-compliant. Requires root. Ideal for proprietary apps.

Local install
/usr/local

Manual installs. Binaries go in /usr/local/bin. Requires root.

User-only (no root)
~/.local/share/{publisher}/{name}

XDG base directory spec. No root required. Add ~/.local/bin to PATH.

.mis File Format

Installer projects are stored as YAML .mis files.

format: mis/1

app:
  name: "My Application"
  version: "1.2.0"
  publisher: "ACME Corp"
  description: "A great application."
  url: "https://example.com"
  identifier: "com.acme.myapp"
  icon: "resources/myapp.icns"
  license-file: "payload/LICENSE.txt"

defaults:
  install-dir:
    macos:   "/Applications/ACME"
    windows: "C:\\Program Files\\ACME\\My Application"
    linux:   "/opt/acme"
  require-admin: true
  allow-custom-dir: true
  launch-after: true
  create-uninstaller: true

components:
  - id: core
    name: "Core Application"
    required: true
    files:
      - src: "payload/MyApp.app"
        dst: "{install-dir}/MyApp.app"

prerequisites:
  - id: homebrew
    name: "Homebrew"
    check-cmd: "which brew"
    install-cmd: "https://brew.sh"
    platforms: [macos]

custom-actions:
  - id: postinstall
    trigger: after-install
    type: shell
    command: "chmod +x \"{install-dir}/MyApp.app/Contents/MacOS/myapp\""
    platforms: [macos]

targets:
  - macos
  - windows

TriggerWhenCommon uses
before-installBefore file copy begins Stop running processes, check disk space, create backup

Build Commands (Developer Reference)

Studio IDE

cmake -B studio/build -S studio \
  -DCMAKE_PREFIX_PATH=$(brew --prefix qt) \
  -DCMAKE_BUILD_TYPE=Debug
cmake --build studio/build -j$(sysctl -n hw.logicalcpu)
codesign --force --sign - studio/build/Mcaster1InstallStudio.app
open studio/build/Mcaster1InstallStudio.app

Runtime Installer

cmake -B runtime/build -S runtime \
  -DCMAKE_PREFIX_PATH=$(brew --prefix qt) \
  -DCMAKE_BUILD_TYPE=Debug
cmake --build runtime/build -j$(sysctl -n hw.logicalcpu)
codesign --force --sign - runtime/build/Mcaster1Installer.app

Incremental rebuild

cmake --build studio/build -j$(sysctl -n hw.logicalcpu) && \
codesign --force --sign - studio/build/Mcaster1InstallStudio.app && \
open studio/build/Mcaster1InstallStudio.app
Always codesign after building on macOS. Stale code-directory cache causes SIGKILL on launch.
